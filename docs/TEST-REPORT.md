## 一、加载计时

| 指标 | 数值 | 说明 |
|---|---|---|
| TTFB（`responseStart`） | **595 ms** | 服务端首字节 |
| First Paint / FCP | **992 ms** | 首次绘制 |
| DOMContentLoaded | **2330 ms** | 主要成本：抖音自身 179 个 JS 的解析执行 |
| load | **2881 ms** | 之后继续拉图片/视频 |
| 资源请求数 | 250（其中 **179 个 JS**） | 字节不多，慢在脚本数量 |
| 传输量 | 0.27 MB | 大量命中缓存 |

**结论**：冷启动时间由抖音自身脚本体量决定，扩展无法显著优化；扩展负责「不额外拖慢 + 首屏不闪 + 不抢主线程」。

首屏不闪：`content/boot.js` 在 `document_start` 注入遮蔽样式与 56px 占位条，主脚本建好栏后加 `html.dcinema-ready` 交班。

## 三、性能：我们自己的开销

| 项目 | 实测 | 备注 |
|---|---|---|
| 一次全文文本扫描 | **1.1 ms**（1222 元素） | `trimChrome` 类工作 |
| 5 秒内 DOM 变动批次 | **109 次（≈22 次/秒）** | 抖音自身渲染 + 播放 |
| 视频 rect 读取 | 0.1 ms | 可忽略 |

优化前：每个变动批次都跑完整清扫（≈3–4 ms）→ 每秒 70–90 ms 主线程（7–9% CPU）。

已实施（`7996ec5`）：

1. **两级调度**：轻活每帧（顶栏/按钮/适配），重活最多 400 ms 一次（全文扫描）
2. **空闲执行**：`requestIdleCallback(timeout: 200)`，页面隐藏时跳过，恢复可见时重置节流
3. **preconnect**：`document_start` 预热静态包 / 图床 / 视频 CDN

## 五、复测步骤

1. `chrome://extensions/` → 抖音扩展 **↻ 重载** → 刷新页面
2. 计时：
   ```js
   const n = performance.getEntriesByType('navigation')[0];
   ({ ttfb: n.responseStart, dcl: n.domContentLoadedEventEnd, load: n.loadEventEnd })
   ```
3. 结构：`.dcinema-bar`、`.dcinema-nav a`、`.dcinema-actions > *`、`.dcinema-account > *`
4. 隐藏项：对 `[data-e2e="video-player-digg|video-player-collect|video-play-more"]`、`.ai-douyin-entry` 查 `getComputedStyle`（**元素仍在 DOM，不能用"存在"判断**）
5. 视频填充：确认 4:3 → `object-fit: contain`；16:9 → `cover`，且 `object-position: center bottom`
6. 进度条：点 **80% 位置**（30% 常与当前播放时间重合，会造成"没反应"的假象）
7. 下载：点「下载」→ ① 页面「已开始」② Chrome 下载气泡出现任务 ③ 完成提示「下载完成（X MB）」④ 文件落在 `%USERPROFILE%\Downloads\douyin\`
8. 搜索历史：点搜索框 → 面板出现；点某行 × → 该条消失；点「清除全部」→ 空状态
9. 消息：点「消息」→ 右侧 356×799 面板，再点收起
10. 详情：点「详情」→ URL 变为 `/video/<当前id>`
11. 个人主页：打开 `/user/<sec_uid>`，悬停作品卡片 → 卡片与预览存活；获赞/粉丝统计可见
